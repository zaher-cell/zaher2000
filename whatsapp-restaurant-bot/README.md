## 1️⃣ MongoDB Atlas — رابط الاتصال

المشروع `Project 0` والكلستر `Cluster0` (Mumbai) جاهزين، وقاعدة البيانات `restaurant-bot`
بكل الـ Collections منشأة مسبقاً. الناقص فقط "مستخدم قاعدة بيانات" (Database User) للحصول على رابط اتصال:

**الطريقة السريعة (يدوياً، دقيقتين):**
1. من Atlas: **Database Access → Add New Database User**
2. Username: `restaurant-bot-app` — ولّد كلمة مرور تلقائية واحفظها
3. Role: `Read and write to any database` (أو حدد `restaurant-bot` فقط)
4. من **Database → Connect → Drivers** انسخ الرابط وعدّله بإضافة اسم قاعدة البيانات:
   ```
   mongodb+srv://restaurant-bot-app:PASSWORD@cluster0.xxxxx.mongodb.net/restaurant-bot?retryWrites=true&w=majority
   ```
5. أرسل لي هذا الرابط في نفس المحادثة وأنا أحطه مباشرة في Railway.

Network Access مفتوح مسبقاً على `0.0.0.0/0` — ما تحتاج تعدل فيه شي.

## 2️⃣ GitHub — رفع الكود

**عندي طريقتين، اختر الأسهل لك:**

### الطريقة أ) أرفعه أنا مباشرة (الأسرع، يعمل من الجوال)
أعطني في نفس المحادثة:
1. اسم المستخدم في GitHub
2. Personal Access Token بصلاحية `repo` كاملة (من جوالك: افتح github.com ← الصورة الشخصية ← Settings ← Developer settings ← Personal access tokens ← Tokens (classic) ← Generate new token ← فعّل صلاحية `repo` فقط ← Generate ← انسخ الكود اللي يبدأ بـ `ghp_`)

⚠️ هذا التوكن مثل كلمة مرور مؤقتة لحسابك — بعد ما أرفع الكود، ارجع واحذفه (Revoke) من نفس الصفحة، هذا إجراء أمان طبيعي وما يأثر على شي بعد الرفع.

بمجرد ما توصلني، أنشئ الريبو وأرفع كل الملفات تلقائياً، بدون أي أوامر منك.

### الطريقة ب) ترفعه أنت يدوياً

cd whatsapp-restaurant-bot
git init && git add . && git commit -m "أول نسخة"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO_NAME.git

## 3️⃣ Railway.app — النشر 24/7

بمجرد ما يصير الكود على GitHub (بأي طريقة من فوق)، أعطني اسم الريبو (مثال: `zaher/whatsapp-bot`)
وأنا أسوي كل شي عبر اتصالي المباشر بـ Railway:
- إنشاء الخدمة من الريبو
- ضبط كل متغيرات البيئة (MONGODB_URI, JWT_SECRET, ADMIN_PASSWORD, ADMIN_ACTIVATION_CODE)
- توليد رابط عام (Domain) للتطبيق
- متابعة حالة أول Deploy

**لماذا Railway بدل Render؟** خطة Railway المجانية لا "تنام" بعد فترة خمول مثل Render Free —
مناسبة أكثر لبوت لازم يكون متصل بواتساب باستمرار.

### لو تحب تسويها يدوياً بدل ما أسويها أنا:
1. [railway.app](https://railway.app) ← New Project ← Deploy from GitHub repo
2. اختر الريبو
3. من تبويب **Variables** أضف:
   | المتغير | القيمة |
   |---|---|
   | `MONGODB_URI` | رابط الاتصال من خطوة 1 |
   | `JWT_SECRET` | القيمة الموجودة بملف `.env.example` (أو ولّد نص عشوائي طويل) |
   | `ADMIN_PASSWORD` | القيمة الموجودة بملف `.env.example` أو كلمة مرور من اختيارك |
   | `ADMIN_ACTIVATION_CODE` | `zaher2006` |
4. Railway يكتشف `railway.json` تلقائياً ويشغّل `node server.js`
5. من **Settings → Networking → Generate Domain** تحصل على رابط عام

## 4️⃣ ربط الواتساب

1. افتح رابط التطبيق (من Railway)
2. سجّل دخول بتبويب **أدمن** وكلمة المرور (ADMIN_PASSWORD)
3. من صفحة **"ربط واتساب"** يظهر رمز QR — امسحه من واتساب:
   **الإعدادات → الأجهزة المرتبطة → ربط جهاز**
4. تتحول الحالة إلى **"متصل ✅"** والبوت جاهز

> جلسة الواتساب تُحفظ داخل MongoDB نفسه، فما راح تحتاج تعيد المسح كل مرة يعاد فيها تشغيل الخدمة.

## كيف يشتغل تدفق الطلب الكامل

```
الزبون يكتب في واتساب → يختار مطعم (لو مغلق يظهر له "مغلق حالياً")
    → يتصفح الأقسام والأصناف → يضيف صنف + ملاحظة اختيارية → يعدّل/يحذف من السلة
    → اسم + جوال + عنوان → كوبون خصم اختياري
    → ملخص كامل (مجموع فرعي + توصيل − خصم = إجمالي) → تأكيد
    → إشعار فوري لصاحب المطعم + حفظ بقاعدة البيانات
    → صاحب المطعم: قبول ← جاهز (من واتساب أو لوحة التحكم)
    → كل السائقين النشطين يأخذون إشعار "طلب جاهز"
    → السائق: استلام ← تسليم
    → الزبون ياخذ إشعار "تم التوصيل" + نقاط ولاء + طلب تقييم (1-5 نجوم)
```

### أوامر الزبون في واتساب
`قائمة` `سلة` `تعديل رقم كمية` `حذف رقم` `طلباتي` `تتبع رقم_الطلب` `نقاطي` `الغاء` `مساعدة`

### أوامر صاحب المطعم
`طلبات` `قبول ORD-...` `جاهز ORD-...` `فتح` `اغلاق`

### أوامر السائق
`استلام ORD-...` `تسليم ORD-...`

### أوامر الأدمن المخفي
`احصائيات` `مطاعم`

## أشياء أضفتها لم تُذكر صراحة (ولماذا كانت ضرورية)

1. **حفظ جلسة الواتساب داخل MongoDB** بدل قرص السيرفر — تفادي إعادة مسح QR مع كل إعادة تشغيل.
2. **صفحة QR داخل لوحة التحكم** بدل تتبع سجلات الاستضافة.
3. **`/health`** endpoint — يفيد فحوصات الجاهزية على Railway.
4. **تسجيل دخول JWT منفصل لكل دور** بدل مفتاح واحد مشترك للكل — كل طرف يشوف بياناته فقط.
5. **زرع تلقائي عند أول تشغيل** (`config/seed.js`) — يعمل من نفسه بدون Terminal، مناسب للجوال 100%.
6. **تجزئة كلمات المرور بـ Node crypto المدمج** بدل مكتبة خارجية — يتجنب مشاكل بناء native modules على منصات الاستضافة المجانية.

## قيود يجب تعرفها
- `whatsapp-web.js` غير رسمي من واتساب — يفضّل تخصيص رقم للبوت بدل رقمك الشخصي لتفادي أي قيود من واتساب على الاستخدام المكثف.
- الخصم بالكوبونات لا يتجاوز قيمة المجموع الفرعي (لن يصير الإجمالي سالباً).
- نقاط الولاء تُمنح فقط عند تأكيد التوصيل (نقطة لكل 10 ريال من إجمالي الطلب).
